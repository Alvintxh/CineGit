# CineGit · 六页路演与三分钟讲稿

## 01 / 问题：一个镜头改了，为什么整部片都要重做？（25 秒）

AI 创作者会同时使用脚本、生图、视频和声音工具。今天分享的往往只是提示词，别人无法完整复现；修改一个镜头又要重跑所有步骤；做过的版本散落在一堆 final 文件里。我们把这些问题当成一个软件工程问题：创作缺少可执行的工作流和增量构建系统。

## 02 / 方案：让每一帧都有来路（25 秒）

CineGit 是一个基于 MCP 的视频创作仓库。生成请求经过网关时，提示词、种子、参数和上下游资产会一起被记录成 DAG。重复的角色和场景可以替换成全局变量，工作流导出为 JSON 后即可复用。

## 03 / 演示：只改第二个镜头（45 秒）

播放「雨夜来信」。选第二个镜头，在提示词加入「日落暖色调」，种子保持不变。点关键帧预览，先看到动态分镜。点击 Commit，观察三个节点中只有一个重新生成。其余两个直接命中缓存，最后用 FFmpeg 流拷贝拼接。强调界面给出实际耗时，离线演示并未调用商业模型。

## 04 / 技术：视频也可以增量编译（30 秒）

节点身份由有效提示词、参数、上游哈希和模型版本共同决定。上游不变，缓存就不变。各模型输出先统一到相同分辨率、帧率、像素格式、时间基与音轨，再进行零视频重编码拼接。修改依赖会传递到下游，没有依赖的镜头则完全不受影响。

## 05 / 版本与分享：挑回最好的那个镜头（35 秒）

打开分支树，比较原版与暖色版本。两栏同步播放，下方展示真实参数差异。选择更好的镜头合入草稿，或者把历史快照回滚为一个新提交。然后去工作流市场 Fork 一份模板，替换主角，复用整套创作逻辑。市场当前演示免费复用与定价流程，不收取真实费用。

## 06 / 下一步：把可复现创作交给所有工具（20 秒）

本地闭环已经覆盖 MCP 录制、DAG、两级预览、缓存、版本和市场。真实模型通过统一 HTTP 网关接入。后续重点是完成主流模型厂商适配、多人协作与真实许可证交易。我们的目标是：创作不再从零开始，每一次修改都只付变化的成本。

## 演示准备

1. 启动服务并播放 main、explore/amber、explore/closeup 三条分支，确认视频已缓存。
2. 演示前保留 main 的原始状态；修改第二个镜头时使用不同于现有缓存的提示词。
3. 可播放的完整 MP4 位于 `.data/outputs/`，每个 Commit 的实际路径可从导出页面或 API 读取，用作断网备份。
4. 外部模型不可用时保持默认离线生成器；演示时清楚说明哪些部分是本地程序化画面，哪些是实际运行的缓存与视频引擎。
